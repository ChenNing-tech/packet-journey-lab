# 数据包传输动画实验室

**PACKET JOURNEY LAB**：面向大一新生的 TCP/IP 教学实验。用确定性的离散事件展示设备处理、协议封装、广播、单播、表项学习和地址变化。

## 启动

环境：Node.js 20.19+ 或 22.12+，推荐当前受支持的 LTS。首次安装依赖需要网络，安装后开发和使用均不依赖在线 CDN。

```bash
npm install
npm run dev
```

打开终端输出的本地地址，默认是 **http://127.0.0.1:5173/**。

```bash
npm test           # 协议、状态机与故障单元测试
npm run build      # TypeScript 检查及生产构建
npm run preview    # 预览 dist，默认 http://127.0.0.1:4173/
```

产物位于 `dist/`，可由任意静态 HTTP 服务器提供。不要直接双击 `index.html` 使用 `file://` 打开 ES Modules。

## 实验场景

| 场景 | 正常流程步骤 | 观察重点 |
| --- | ---: | --- |
| 同一局域网内 Ping | 26 | 同网段判断、ARP 广播与单播应答、交换机学源查目的、ICMP 往返 |
| 跨网段 Ping | 56 | 默认网关、路由匹配、两侧 ARP、解封装、TTL、二层重新封装 |
| ARP 地址解析 | 14 | Request / Reply、广播域、双方缓存、MAC 表 |
| 访问 Web 服务器 | 208 | DNS → ARP → TCP 握手 → HTTP GET / 200 → 数据确认 → 四次挥手 |
| DNS 域名解析 | 27 | 本地 DNS 缓存、解析 DNS 服务器 MAC、UDP 53、A 记录 |
| DHCP 自动获取地址 | 22 | Discover → Offer → Request → ACK，ACK 到达后应用配置 |
| TCP 三次握手 | 72 | 包含必要 ARP 与每次经过交换机 / 路由器的处理，SYN / SYN-ACK / ACK |
| TCP 连接释放 | 137 | 从冷缓存和握手开始，展示双向 FIN / ACK、半关闭、TIME-WAIT |

每一段交换机转发、路由器处理都占用独立步骤，因此综合场景比只有协议消息的概览更长。可使用时间线上的阶段按钮跳到 DNS、TCP、HTTP 或连接释放。

故障演示提供 10 种故障：IP / 掩码配置错误（/16 掩码实例）、网关为空、网关跨子网、主机关机、交换机接入接口关闭、路由器接入接口关闭、目标网络缺路由、VLAN 不匹配、错误 DNS 地址、TTL 归零。选择故障会切换到适用场景、清空此前状态；每个故障在具体位置停止并给出原因、诊断线索与修复方法。

## 如何使用

1. 左侧选择场景，阅读难度、协议、步骤数和本节学习目标。「收起」保留八个图标入口；临时展开时选完自动收起，图钉按钮固定展开。点击场景栏外部或 Escape 可关闭临时展开，状态会在本机记忆。
2. 「播放 / 暂停」控制自动播放；「上一步 / 下一步」停在指定事件完成后的状态。
3. 可选 0.5×、1×、1.5×、2×；「重播当前步骤」只播放当前事件的动画，结束后暂停，不进入下一步；「重置」回到初始事件并清空表项。
4. 时间线支持拖动滑块、点击任意步骤和阶段跳转。跳转后同时恢复数据包、表项、地址对比、连接状态和动画位置。
5. 右侧「数据包检查器 / 设备透视」标签共用检查窗口。点击设备会暂停播放并切到设备透视，展示 MAC 表、ARP、接口、路由与内部处理；「地址变化表」比较路由器前后的地址，完整表格可横向滚动。拓扑右上角「设备表项 / 对比地址」也能切换，Escape 返回包检查器。
6. 右侧检查器按由外到内的顺序展开协议层，眼睛按钮隐藏 / 显示字段。关键字段优先显示，其余字段可展开查看；经过 R1 时，地址与 TTL 显示「已变化 / 未变化」，变化项附原值。黄色表示当前讲解重点；地址对比表中的黄色表示相对同方向前一段链路发生了变化。
7. 「课堂讲解」卡片位于拓扑画布内，展示当前步骤的解释、问题与答案，支持收起和关闭；顶部按钮可重新打开。点击「编辑」可修改当前场景、当前步骤的讲解正文、思考题、参考答案及误区注释，保存后会显示「已自定义」，并按场景和步骤保存在本机浏览器。编辑会自动暂停播放；「取消」丢弃未保存内容，「恢复默认」需再点击「保存修改」才会生效。点击虚线术语查看注释，「常见误区与补充注释」可展开。切换步骤会清除上一题的答案和注释。
8. 「使用指南」说明操作与模型边界。非表单焦点下，空格切换播放，左右方向键逐步观察。全屏按钮使用浏览器 Fullscreen API。

动画和状态采用明确的时间语义：**当前事件的设备状态与字段展示该事件结束后的快照；协议胶囊播放该事件的可视路径。** 单步与跳转的胶囊停在路径终点。重播不会重复追加表项。

### 参考图视觉优化

- 路由器采用蓝色圆柱与四向路由标识，交换机显示立体机身和 RJ45 端口，PC 显示屏幕、底座、键盘和鼠标，服务器使用塔式机箱与状态灯。所有图标为本地 SVG，拓扑与场景列表复用，无在线图片依赖。
- 页首使用紧凑工具栏：左侧为标题、场景与步骤，右侧依次为播放、上一步、下一步、重播本步、重置、四档倍速、课堂讲解和全屏。移除拓扑上方重复的场景标题，底部时间线独占一行。
- 借鉴用户提供的本地参考项目，讲解卡片移入拓扑画布，位于设备绘图区下方，不覆盖设备或链路；右侧包检查和设备透视采用并排标签。参考项目只读，未改动其文件，也未引入其协议模型。
- 移除设备底部的选中圆环和椭圆阴影；路由器使用完整圆柱轮廓和四个向外箭头。选中设备通过名称颜色提示，键盘焦点保留矩形虚线框。
- 两台 PC 共用一条垂直轴，多个服务器共用另一条垂直轴；两个网段标签保持同一水平基线。DNS 虽与 Web 服务器按列对齐，仍通过上方独立连线接入 SW1，连线注明所属网段，数据包沿该实际路径移动。
- 设备状态、当前位置标记和新帧提示均由当前事件驱动。
- 路由器处理卡片展示解封装、路由查询、TTL 与重新封装进度；交换机卡片展示源 MAC 学习和出入端口。
- 窄屏保留设备的可读尺寸，可左右拖动拓扑；步骤切换会定位到当前设备，「查看全图 / 放大设备」切换完整拓扑与详细视图。
- 保留原来的八个场景、十种故障、单步回放及表项快照语义；参考图只影响显示方式，不替换实际协议字段或缩减流程。

## 默认地址

同网段：PC1 `192.168.1.10/24`、PC2 `192.168.1.20/24`，均接 SW1。增加旁路 R1 接口，便于观察广播同时向多个端口复制及路由器隔离广播；Ping 本身不经过 R1。

跨网段：PC1 `192.168.10.10/24` → SW1 → R1 → SW2 → Server1 `192.168.20.100/24`。R1 两个接口分别为 `192.168.10.1/24` 与 `192.168.20.1/24`。DNS Server 位于 `192.168.10.53`；固定教学域名 `www.example.test` 的 A 记录为 `192.168.20.100`。

DHCP：PC1 初始 `0.0.0.0`；服务器 `192.168.1.2`，提供 `192.168.1.100/24`、网关 `192.168.1.1`、DNS `192.168.1.2` 和 86400 秒租期。

### 确定性实现

- `createScenario` 生成带唯一 ID 的有序事件，事件包含发送 / 接收设备、路径、说明、教师讲解、问题与答案、数据包快照、表项变更、层和字段重点、误区与可选失败原因。
- `applyChanges` 以纯函数应用一个事件，复制状态后按 MAC+VLAN 或 IP+接口更新表项。`compileSnapshots` 生成各步骤快照；`stateAt` 从初始状态重算，用于验证任意时间线跳转的正确性。
- 播放器只存储步骤、步骤进度、播放状态、速度和重播标记。单一 `requestAnimationFrame` 驱动 `TICK`，没有用零散 `setTimeout` 编排协议。
- 暂停保留动画位置；选择设备、单步和跳转会暂停。故障为终止事件，不生成后续成功事件。
- ARP 处理、交换机源地址学习 / 目的地址查询、路由器处理为共享流程。Web / TCP / Ping 都使用相同转发模型。
- 表项老化不与墙上时钟绑定，避免后台停留或不同播放速度导致状态不可重现。

## 教学模型边界

- 不是真实协议栈、设备模拟器或抓包软件；不调用操作系统 Ping，也不发起真实 DNS / HTTP / DHCP 请求。页面展示的是本地教学数据。
- 不模拟 NAT、IPv6、TLS / HTTPS、真实网络 I/O、重传定时器、拥塞控制、分片、链路误码、完整 ICMP 差错返回或动态路由协议。
- IPv4 首部为 20 字节，固定 Identification 与 DF；首部校验和根据展示字段实际计算，并随 TTL 修改更新。
- 以太网 FCS 只说明作用，不生成可在线路上传输的帧；ICMP / TCP 校验和未逐字节构造。IPv4 UDP Checksum 设为 0，表示本教学 IPv4 场景不启用可选的 UDP 校验。
- DNS 演示一个固定 A 记录、一个客户端查询；未展开递归 / 迭代解析。DNS TTL 是缓存时间，与 IP TTL 不同。
- DHCP 选择客户端 Broadcast flag=1 的 DORA 分支，因此 Offer / ACK 也用广播；真实 DHCP 的应答方式取决于客户端状态和广播标志。未展开地址冲突探测、租约续租、多个服务器竞选或 DHCP Relay。
- TCP 握手初始序号固定为客户端 1000、服务器 5000；SYN / FIN 各消耗一个序号，纯 ACK 不消耗序号；HTTP 的实际 UTF-8 字节长度推进 seq / ack。挥手展示分开的四条消息；真实实现可以合并 ACK 与 FIN。
- TIME-WAIT 2MSL 用一个明确标记的教学快进事件表示；MAC 老化 300s、DNS 缓存 TTL 300s、DHCP 租期显示值均不实时倒计时。
- 目标故障停在丢弃 / 无下一跳 / 无应答的最早可解释位置；不伪装成真实抓包的“请求超时”。

## 协议参考

实现所用的一手规范参考：

- [RFC 826：ARP](https://www.rfc-editor.org/rfc/rfc826)（请求、应答和接收时学习发送方映射）
- [RFC 2131：DHCP](https://www.rfc-editor.org/rfc/rfc2131)（DORA、客户端状态及广播分支）
- [RFC 9293：TCP](https://www.rfc-editor.org/rfc/rfc9293)（握手、序号空间、连接释放）

教学简化不能替代完整规范；生产网络诊断仍应使用真实设备状态和抓包工具。
