## 验证方法

- 每个正常场景均从空缓存出发，在 Node 单元测试中逐事件重建快照并与顺序运行结果比较，再在 Chromium 中逐事件点击时间线核对界面。
- ARP 测试检查全 F 目的 MAC、单播应答、请求方 / 应答方缓存、交换机学源地址、广播不回入端口且不跨路由器。
- 跨网段测试检查两侧 MAC 变化、同方向端到端 IP 不变、64→63 的 TTL、IP 首部校验和、去除原以太网帧与重新封装。
- TCP 检查三次握手、四次挥手、字节数推进序号、纯 ACK 不占序号、双方状态以及 TIME-WAIT 教学快进。
- DHCP 检查 DORA、68/67 端口、Broadcast flag 分支，以及 ACK **到达客户端后**才应用配置。
- 实际浏览器测试证明暂停保持动画坐标、重播只播放当前步骤、回退恢复空表、修改接口状态只关闭对应链路。

### 数字信号与数据交换实验室

新增浏览器用例验证三个实验室入口、URL Hash 前进后退、数字编码参数与算法波形、连续播放与暂停、播放结束后重播、同轴双编码对比、波形解码挑战，以及 320、390、768、1024、1512px 视口下无整页横向溢出。32 位序列在移动端保留页面宽度，并在画布内部横向滚动。

数据交换实验另用 11 项单元测试验证：三种方式均能到达，电路必须建立后才能传输并在完成后释放，报文在每个中间节点完整存储后才转发，分组可流水传输和乱序到达，链路故障只走真实替代路径，两条出口均断时不伪造到达，恢复事件可使等待分组继续，拥塞会增加时延，同一配置可生成相同事件序列。浏览器测试覆盖三种顶部模式、四台路由器拓扑、乱序重组展示、链路故障 / 恢复控制和时间线回放。

教学任务新增 5 项纯函数测试和 3 项浏览器流程测试。编码任务必须观察每个目标位，直接拖到末位仍保持进行中；解码任务依赖真实答案判定。交换任务必须显示对应的建立 / 存储 / 到达 / 释放 / 链路变化事件。浏览器实际完成全部 7 项任务，验证两个实验室的演示模式关键步骤自动暂停、自由探索、下载 JSON 和重新实验清零。导出记录不包含姓名或学号字段，页面未新增登录和外部上传请求。

收尾验收新增两个浏览器用例，并加强已有导出测试：读取下载的 JSON，核对任务状态、操作、观察结果及完成任务时的配置；实际验证多位自由播放结束后自动停止、再次播放从起点重播、工作区键盘操作、触摸选位和链路控制。交换参数变化后不会把旧配置的建立事件与新配置的释放事件拼成任务完成证据。本轮相关 11 项浏览器用例、76 项单元测试与 TypeScript/Vite 构建通过。原有 28 项数据包及工作台用例在最近完整回归中通过。
